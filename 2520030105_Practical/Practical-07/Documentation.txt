Objective:
To implement POSIX signal handling in a C program, register
custom signal handlers for SIGINT, SIGTERM, and SIGUSR1,
and observe signal delivery using commands from another
terminal.

Requirements:
1. Register signal handlers using signal() system call.
2. Handle SIGINT (Ctrl+C interrupt).
3. Handle SIGTERM (termination request).
4. Handle SIGUSR1 (user-defined signal 1).
5. Demonstrate signal handling from another terminal.

Source File:
src/sighandle.c

Output Files:
outputs/sighandle_output.txt

Program Design:

  Signal Handlers:
    - handle_sigint():  Handles SIGINT (signal 2).
      Prints a message and continues execution.
      Triggered by Ctrl+C or kill -SIGINT <pid>.

    - handle_sigterm(): Handles SIGTERM (signal 15).
      Prints a message and exits gracefully.
      Triggered by kill -SIGTERM <pid> or default kill.

    - handle_sigusr1(): Handles SIGUSR1 (signal 10).
      Prints a message and continues execution.
      Triggered by kill -SIGUSR1 <pid>.

  Main Program:
    1. Register three signal handlers using signal().
    2. Display the process PID.
    3. Display the registered handlers.
    4. Print instructions for sending signals.
    5. Enter an infinite loop calling pause().
       pause() suspends the process until a signal is caught.

  Signal Flow:

    Terminal 1 (sighandle)          Terminal 2 (commands)
    ────────────────────            ─────────────────────
    Register handlers
    PID: 4501
    Waiting for signals...
                                    kill -SIGINT 4501
    Caught SIGINT, continues
                                    kill -SIGUSR1 4501
    Caught SIGUSR1, continues
                                    kill -SIGTERM 4501
    Caught SIGTERM, exits

Signals Handled:

  Signal    Number   Default Action   Handler
  ------    ------   --------------   -------
  SIGINT       2     Terminate        handle_sigint (continue)
  SIGTERM     15     Terminate        handle_sigterm (exit)
  SIGUSR1     10     Terminate        handle_sigusr1 (continue)

  Note: SIGUSR1 and SIGUSR2 are reserved for user-defined
  purposes. The default action for all three signals is to
  terminate the process, but our handlers override this.

Result:
The program successfully demonstrates POSIX signal handling
by registering custom handlers for three different signals.
SIGINT and SIGUSR1 handlers allow the process to continue
running after receiving the signal, while the SIGTERM handler
performs a graceful exit. Signals were sent from another
terminal using the kill command and were correctly caught
and handled by the program.

Conclusion:
POSIX signals provide a software-based mechanism for
inter-process communication and process control. The
signal() system call allows a process to register custom
handlers for specific signals, overriding the default
termination behavior. SIGINT is typically generated by
the terminal (Ctrl+C), SIGTERM is sent by the kill command
by default, and SIGUSR1/SIGUSR2 are available for
user-defined purposes. The pause() system call is useful
for suspending a process until a signal is received.
