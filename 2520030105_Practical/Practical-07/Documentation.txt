Objective:
To handle POSIX signals (SIGINT, SIGTERM and SIGUSR1) in a C
program using the signal() system call, and to verify the
handlers by sending signals to the process from another
terminal using the kill command.

Requirements:
1. Register a signal handler using signal().
2. Handle SIGINT (interrupt from keyboard / kill -INT).
3. Handle SIGTERM (termination request).
4. Handle SIGUSR1 (user-defined signal 1).
5. Display the process PID and verify the handlers by sending
   signals from another terminal.

Source File:
src/sighandle.c

Output Files:
outputs/sighandle_output.txt

Program Design:

  Signal Handler:

    void handler(int sig):
      - If the signal is SIGINT, prints "SIGINT received".
      - If the signal is SIGTERM, prints "SIGTERM received".
      - If the signal is SIGUSR1, prints "SIGUSR1 received".

  Main Program:
    1. Register handler() for SIGINT, SIGTERM and SIGUSR1
       using signal().
    2. Print the process PID ("Process ID: <pid>").
    3. Enter an infinite loop:
         - Print "Running...".
         - sleep(2).
       The process keeps running until the signals are sent.

  Signal Delivery:

    Terminal 1 (sighandle)             Terminal 2 (commands)
    -----------------------            ---------------------
    Register handlers
    Process ID: 4938
    Running...                         kill -INT 4938
    SIGINT received (handler runs)
    Running...                         kill -USR1 4938
    SIGUSR1 received (handler runs)
    Running...                         kill -TERM 4938
    SIGTERM received (handler runs)
    Running...

Signals Handled:

  Signal    Number   Source                       Handler action
  ------    ------   ------                       --------------
  SIGINT       2     Ctrl+C or kill -INT <pid>    prints SIGINT received
  SIGTERM     15     kill -TERM <pid>             prints SIGTERM received
  SIGUSR1     10     kill -USR1 <pid>             prints SIGUSR1 received

  The default action of these signals is to terminate the
  process, but the registered handler overrides the default
  and only prints a message. So the process continues running.

Observations:

  The kill -INT, kill -USR1 and kill -TERM commands were sent

Compilation and Execution:

  gcc -o sighandle sighandle.c
  ./sighandle

  In another terminal, send signals to the process:
  kill -INT  <pid>
  kill -USR1 <pid>
  kill -TERM <pid>

  The <pid> is the value printed by the program.

Result:
The program successfully demonstrated POSIX signal handling.
The signal() system call registered one handler for SIGINT,
SIGTERM and SIGUSR1. Sending kill -INT, kill -USR1 and
kill -TERM from another terminal correctly triggered the
handler, which printed "SIGINT received", "SIGUSR1 received"
and "SIGTERM received" respectively. The process kept running
after each signal.

Conclusion:
POSIX signals provide a way for the kernel or another process
to notify a process of events. The signal() system call
registers a custom handler that overrides the default action of
a signal. SIGINT is generated by Ctrl+C or kill -INT, SIGTERM
is a termination request from kill (default), and SIGUSR1 is a
user-defined signal. Since the handler only prints a message,
the process continued running after each signal was received.
