Program Design:

The program creates distinct observable stages:

Stage 1: Parent starts and displays its PID/PPID.
Stage 2: fork() creates a child process.
Stage 3: Both parent and child display their PIDs.
Stage 4: Child enters sleep() for 5 seconds (Waiting state).
         Parent calls waitpid() (also Waiting/sleeping).
Stage 5: Child wakes up and performs computation (Running state).
Stage 6: Child exits (Terminated state).
Stage 7: Parent resumes after waitpid() and exits.

The program reads /proc/<pid>/stat and /proc/<pid>/status at each
stage to show the actual kernel-tracked process state.

Process States:

Linux uses the following state letters in /proc/<pid>/stat:

  R = Running or Runnable
      Process is executing or ready to run on a CPU.

  S = Interruptible Sleep (Waiting)
      Process is sleeping waiting for an event (e.g., timeout,
      I/O completion, signal).

  D = Uninterruptible Sleep
      Process is waiting for I/O and cannot be interrupted.

  T = Stopped
      Process has been stopped by a signal (e.g., SIGSTOP).

  Z = Zombie
      Process has exited but parent has not yet collected its
      exit status via wait().

Mapping to Textbook States:

  Textbook        Linux (/proc)         Explanation
  --------        -------------         -----------
  Ready           R (Runnable)          Process is in the run queue,
                                        waiting for CPU time.

  Running         R (Running)           Process is currently executing
                                        on a CPU. In ps/top, R covers
                                        both ready and running.

  Waiting         S (Sleeping)          Process is blocked waiting for
                                        an event (sleep(), wait(),
                                        I/O).

  Terminated      Process exited        Process no longer exists in
                  (not in ps)           /proc. Parent collects status
                                        via wait()/waitpid().

Note: Linux does not distinguish between "Ready" and "Running" in
the state letter. Both are shown as R. A process in the run queue
but not yet on a CPU is technically "Ready/Runnable." A process
currently on a CPU is "Running." The ps command shows both as R.

Process Lifecycle Analysis:

1. Created (fork):
   fork() creates a new process. The child starts in R (runnable)
   state immediately after creation.

2. Running:
   Both parent and child execute instructions. The child performs
   a computation loop, visible as R state in /proc.

3. Waiting:
   The child calls sleep(5), entering S (interruptible sleep).
   The parent calls waitpid(), also entering S state until the
   child terminates.

4. Terminated:
   The child calls exit(0), terminating the process. The parent
   collects the exit status via waitpid() and continues.

Parent-Child Relationship:

  PID 318 (bash)
    |
    +-- PID 401 (parent, process_states)
          |
          +-- PID 409 (child, process_states)

The parent (PID 401) is a child of bash (PID 318).
The child (PID 409) is a child of the parent (PID 401).
After the child exits, the parent collects its status and continues.

Conclusion:
The practical demonstrates that Linux processes go through distinct
states during their lifecycle. The fork() system call creates a new
process, and the kernel tracks each process's state in /proc. The
ps command shows process states as single letters (R, S, D, T, Z),
while /proc/<pid>/status provides detailed status information.
The wait()/waitpid() system calls allow parent processes to
synchronize with child process termination, completing the process
lifecycle.
