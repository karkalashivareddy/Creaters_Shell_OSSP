Program Design:

zombie.c:
  Step 1: Parent calls fork() to create a child process.
  Step 2: Child prints its PID and exits immediately using
          exit(0).
  Step 3: Parent prints its PID and calls wait(NULL).
          wait() collects the child exit status, so the
          zombie entry is removed from the process table.
  Step 4: Parent prints "Parent process completed" and exits.
  Note: The commented sleep(30) line shows how the child can
  be kept as a zombie for a longer time for observation.

zombie1.c:
  Step 1: A for loop runs 3 times, calling fork() each time.
  Step 2: Each child prints its number and PID and exits
          immediately.
  Step 3: The parent prints its number and PID, then sleeps
          for 40 seconds WITHOUT calling wait().
  Step 4: During the sleep, the exited child is a zombie (Z
          state) in the process table.
  Step 5: After the sleep the parent prints "Parent process
          complete" and creates the next child.
  Step 6: The zombie children stay in the process table until
          the parent exits, after which init/systemd adopts
          and reaps them.

Zombie Process:

A zombie process is a process that has completed execution
(exit()) but still has an entry in the process table. This
happens because the parent has not yet read the child's exit
status using wait().

  Process Lifecycle:
    Running -> Terminated -> Zombie -> (wait()) -> Removed

  Parent calls wait()/waitpid():
    The kernel removes the zombie entry from the process
    table and the parent receives the child's exit status.

  Parent does NOT call wait():
    The zombie entry remains in the process table. In ps -l
    it is shown with state Z and no memory (SZ = 0). When the
    parent exits, init/systemd adopts the zombie and reaps it.

Compilation and Execution:

  gcc -o zombie zombie.c
  ./zombie

  gcc -o zombie1 zombie1.c
  ./zombie1

  While zombie1 is running, in another terminal:
  ps -l | grep zombie1

Result:
Both programs demonstrate zombie process behavior. zombie.c
creates a child that exits and is immediately reaped by the
parent's wait() call. zombie1.c creates three children that
exit while the parent sleeps for 40 seconds without waiting,
leaving each child in the zombie (Z) state. The ps -l output
clearly shows the Z state with SZ = 0 for the exited child.

Conclusion:
A zombie process is created when a child process exits before
its parent collects the exit status with wait(). The exited
process keeps its entry in the process table as a zombie until
the parent calls wait()/waitpid() to collect its status. If the
parent never calls wait(), the zombie remains until the parent
itself exits, after which init/systemd adopts and reaps it.
The ps -l output shows zombies in state Z with size 0.
