To develop a C program that copies file contents using the system

4. Use read() to read data from the source.

6. Handle partial writes correctly.
7. Use close() for both file descriptors.

Algorithm:
1. Parse command-line arguments for source and destination filenames.
2. Open the source file in read-only mode using open().
3. Open/create the destination file with write and create flags.
4. Enter a loop:
   a. Read a block of data from source using read().
   b. Write all read bytes to destination using write().
   c. Handle partial writes by tracking remaining bytes.
5. Close both file descriptors using close().
6. Report the total bytes copied.

System Call Explanation:

open():
Transitions from user space to kernel space to request file access.
The kernel validates permissions, locates the file in the filesystem
(VFS layer), and returns a file descriptor (integer) to the user
program. This descriptor is an index into the process's file
descriptor table maintained by the kernel.

read():
The user program passes the file descriptor, buffer pointer, and
byte count. The kernel copies data from the file's buffer cache
(page cache) into the user-space buffer. This involves a context
switch from user mode to kernel mode. The kernel may need to
fetch data from disk if it is not already cached.

write():
Similar to read() but in reverse. The kernel copies data from the
user-space buffer into the kernel's buffer cache. The actual disk
write may be deferred by the kernel's write-back mechanism.
The user program does not directly control when data reaches disk.

close():
Releases the file descriptor and associated kernel resources.
The kernel removes the entry from the file descriptor table.
If the file was modified, the kernel ensures data is eventually
written to disk.

These functions provide user-space interfaces to kernel services.
Applications cannot directly access hardware or filesystem internals;
they must use system calls as the interface.

strace Experiment:

The strace utility was used to trace all system calls generated by:

    strace cat outputs/sample.txt

The trace was captured to: outputs/strace_cat_sample.txt

Actual strace observations (139 syscalls traced):

1. execve("/usr/bin/cat", ["cat", "outputs/sample.txt"], ...)
   - The kernel loads the cat binary and starts execution.
   - This is the initial system call that replaces the process image.

2. brk(NULL) / brk(0x5a49b6c2f000)
   - Memory management: adjusts the program break (heap area).

3. mmap(NULL, 8192, ...)  (multiple mmap calls)
   - Maps shared libraries (libc, libgcc_s, libm, libselinux, etc.)
     into the process address space.

4. openat(AT_FDCWD, "/etc/ld.so.cache", O_RDONLY|O_CLOEXEC) = 3
   openat(AT_FDCWD, "/usr/lib/x86_64-linux-gnu/libc.so.6", ...) = 3
   - Opens the dynamic linker cache and shared libraries.

5. read(3, "\177ELF...", 832) = 832  (multiple reads)
   - Reads ELF headers and library data from shared objects.

6. fstat(3, {...})  (multiple fstat calls)
   - Gets file status information for opened file descriptors.

7. close(3)  (multiple close calls)
   - Closes file descriptors for libraries after mapping.

8. mprotect(...)  (multiple calls)
   - Sets memory protection flags for mapped library regions.

9. access("/etc/selinux/config", F_OK) = -1 ENOENT
   - Checks SELinux configuration (not present in this WSL).

10. openat(AT_FDCWD, "outputs/sample.txt", O_RDONLY|O_CLOEXEC) = 3
    - Opens the actual target file for reading.

11. fstat(3, {st_mode=S_IFREG|0777, st_size=293, ...}) = 0
    - Gets file metadata (size 293 bytes).

12. splice(3, NULL, 1, NULL, 1048576, 0) = 293
    - Efficiently transfers 293 bytes from file to pipe (stdout).
    - splice() is a zero-copy mechanism in the kernel.

13. close(3) = 0
    - Closes the sample.txt file descriptor.

14. exit_group(0) = ?
    - Process exits with status 0.

Analysis of System Calls:

Directly related to file reading/display:
- openat(): Opens the file - transitions to kernel VFS
- fstat(): Gets file metadata from kernel inode information
- splice(): Reads and transfers file data to stdout (zero-copy)
- close(): Releases file descriptor back to kernel

Runtime/loader/environment calls:
- execve(): Program loading and execution
- brk(): Heap memory management
- mmap()/munmap(): Memory mapping for shared libraries
- mprotect(): Memory protection setup
- access(): Filesystem permission checks
- rt_sigaction(): Signal handler configuration
- arch_prctl(): Architecture-specific register setup

These loader calls set up the process environment before cat begins
its main task of reading and displaying the file.

Conclusion:
The practical demonstrates that all file operations in Linux go
through system calls, which transition execution from user space
to kernel space. The kernel mediates all hardware and filesystem
access through VFS, page cache, and device drivers. Applications
use file descriptors as opaque handles to kernel-managed resources.
The strace experiment confirms that even displaying a small file
involves numerous system calls for process setup, library loading,
file access, and process cleanup.
